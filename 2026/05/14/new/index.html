1、XSS漏洞

反射型XSS

性质：混淆了前端与用户输入，一般出现在搜索框，可控制的输入，在input中出现可输入值value

原理：没有对用户输入做过滤，导致用户输入js代码可以反射到页面中(把用户的输入当作网页代码解析了)

防范措施：

1、.htmlspecialchars(将js代码转换成html实体，用户无法输入js特殊字符)

2、输入白名单校验

3、过滤url参数与跳转

一般网页包含三种编码urlcode、HTML实体编码、js

解码优先级HTML实体编码--->urlencode--->jsunicode

cronjobs提权

定时任务提权

**产生原因：**定时任务被设定以更高的用户权限执行，并且任务文件对其他用户有读写权限，使得其他用户可以更改该文件中的内容

shaodow提权（最不可能成功的）

通过/etc/shadow文件提权的方法

先通过信息收集—>收集子域名—>利用漏洞拿下了一个网站的webshell

产生原因：由于操作失误，使/etc/shadow对其他用户有读写权限，因此其他用户可以更改加密后的密码

**具体操作：**由于有该文件的写权限，可以删除原来账户的密码，然后修改成自己生成的哈希密码

/etc/shadow文件的内容含义：

linux的密码信息保存在两个文件中，分别为/etc/passwd和/etc/shadow其中/etc/shadow文件中包含9个字段，用:隔离开来

sudo提权

SUID提权

ubuntu 20之前是可以直接成功的

SUID成功的前提时命令有suid权限，并且该命令在执行时可以执行其他命令

**原理：**由于某些命令的执行需要root权限，在命令执行时普通用户的权限直接提升为root，命令结束后 又会回到普通用户

暴力破解提权

**实质：**使用ssh来暴力破解root密码

实用性低，因为直接使用ssh去爆破会被防火墙拦截并且封锁ip

工具：hydra

hydra -l root -P passlist.txt ssh://192.168.0.1

跳板文件提权

当不能直接提权至root权限时，先通过提权到其他普通用户，在通过该用户提权到root用户

条件过于苛刻，必须看到普通用户密码

序列化的功能：便于存储

__toString 当一个对象被当作一个字符串被调用，把类当作字符串使用时触发，返回值需要为字符串，例如echo打印对象就会调用此方法**(相当重要)** 打印，拼接
__wakeup() 使用unserializ时触发，反序列化恢复对象之前调用该方法 当反序列化时执行
__sleep() 使用serialize时触发，再对象被序列化前自动调用，该函数需要返回以类成员变量名作为元素的数组(该数组里的元素会影响类成员变量是否被序列化，只有出现在该数组里的成员变量才会被序列化) 序列化时执行
__destruct() 在对象被销毁时触发 在对象被销毁时触发

__callStatic() 在静态上下文中调用不可访问的方法时触发 静态上下文中调用不可访问的方法时
__get() 读取不可访问的属性的值时会被调用（不可访问包括私有属性，或者没有被初始化的属性）用的多 读取不可访问的属性的值时
__isset() 在给不可访问属性调用isset()或empty()时触发 给不可访问属性调用isset()或empty()时
